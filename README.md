# Pantry Keeper

An Android app for keeping track of long-life food in your pantry. Photograph a
product and its best-before date, and an AI vision model fills in the name and
expiry for you. Items are organised by shelf, and you get a reminder a
configurable number of days before something expires.

Everything stays on the phone. There is no account and no backend. The only
network traffic is the label photo you choose to send to an AI model.

## Features

- **Scan to add.** Take a photo of the product (barcodes are picked up too),
  then of the expiry date. The AI suggests the name and date, and you can
  correct both before saving.
- **Shelves.** Name your own shelves, put items on them, and move items between
  them.
- **Expiry reminders.** Local notifications at 09:00, a set number of days
  before each item expires (30 by default).
- **Choose your AI:**
  - **OpenRouter.** Use any vision model on [OpenRouter](https://openrouter.ai)
    with your own API key. The default is `google/gemini-3.8-flash`. The key is
    kept in Android's secure storage and is sent only to OpenRouter.
  - **Local AI.** Any OpenAI-compatible server on your network, for example
    [Ollama](https://ollama.com) with a vision model such as
    `llama3.2-vision`. With this option, photos never leave your network.

## Install

Download the APK from the
[latest release](https://github.com/tezz123/Pantry-Keeper/releases/latest), or
add `https://github.com/tezz123/Pantry-Keeper` to
[Obtainium](https://github.com/ImranR98/Obtainium) to get updates
automatically. Builds are for **arm64** devices, which covers practically all
phones from the last several years.

### Setting up the AI

Open **Settings → Label reading**:

- **OpenRouter:** create a key at <https://openrouter.ai/keys>, paste it in and
  tap **Save key**. You can change the model to any OpenRouter model that
  accepts images.
- **Local AI:** enter the server's base URL, for example
  `http://192.168.1.20:11434/v1` for Ollama, and the model name. Use the
  computer's LAN IP address, not `127.0.0.1`. The phone must be able to reach
  the server, and the server must listen on the network (for Ollama, set
  `OLLAMA_HOST=0.0.0.0`).

## Development

Requirements: Node.js 22, pnpm 10 (`corepack enable` or
`npx pnpm@10.34.6`). For native builds you also need JDK 17 and the Android SDK.

```sh
pnpm install
pnpm run typecheck
pnpm --filter @workspace/pantry-keeper run dev       # Metro / Expo dev server
pnpm --filter @workspace/pantry-keeper run android   # build and run on a device/emulator
```

The app lives in `artifacts/pantry-keeper` (Expo SDK 57, React Native 0.86,
expo-router). The native `android/` directory is generated by `expo prebuild`
and is not committed. Make native changes through `app.json` or config plugins
in `artifacts/pantry-keeper/plugins/`.

More detail on architecture, conventions and pitfalls is in
[`AGENTS.md`](AGENTS.md).

## Releases

GitHub Actions builds a release APK on every push to `main` and on every pull
request. Pushing a `v*` tag, or running the workflow by hand, also publishes a
GitHub Release.

1. Bump `android.versionCode` (and `version`) in
   `artifacts/pantry-keeper/app.json`.
2. Push to `main`. This also fills the build caches that tag builds reuse.
3. Tag and push: `git tag v1.2.0 && git push origin v1.2.0`.

To sign with your own key, add the repository secrets `KEYSTORE_BASE64` (the
keystore file, base64-encoded), `KEYSTORE_PASSWORD`, `KEY_ALIAS` and
`KEY_PASSWORD`. Without them, the APK is signed with a debug key. That works
for sideloading, but an APK signed with a different key can't be installed as
an update over it.
